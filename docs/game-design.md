# 字戰・三國（TDWordWar）遊戲規格說明書 v0.1

> 文字塔防：每個「字」都是一座塔，字有本義與屬性；相鄰的字組成詞（武將名／兵種名）時，融合成更強的單位並獲得對應技能。

---

## 0. 一句話定位

**在格狀戰場上抽字、放字、組字成將，擋住一波波來襲的賊寇。**

- 類型：格狀塔防 + 抽卡合併 + 組詞（Word Building）
- 平台：Web（手機瀏覽器優先，直式 9:16），可包成 PWA
- 單局時長：8～15 分鐘（章節模式）／無限模式不限
- 操作：全程單指拖放與點擊

---

## 1. 設計支柱（Design Pillars）

1. **字即是塔** — 玩家看到「弓」就知道遠程、看到「騎」就知道快速衝撞。規則來自漢字本義，不需要教學。
2. **組詞的驚喜** — 隨機抽到的字彼此有語義關係。玩家發現「原來『關』＋『興』可以成將」的瞬間是本作最大的樂趣點。
3. **空間就是策略** — 組詞需要相鄰，射程需要位置，兩者互相拉扯。棋盤上沒有「隨便放」的格子。
4. **每局都不同** — 抽字隨機 + 配方眾多，逼玩家臨場改變陣容規劃。

---

## 2. 核心循環

```
        ┌──────────────────────────────────────────┐
        │  波次開始 → 敵人沿路徑進攻 → 單位自動攻擊  │
        │      ↓ 擊殺獲得「糧」                     │
        │  用糧「征兵」→ 抽 N 個隨機字進手牌         │
        │      ↓ 拖放到空地                        │
        │  相鄰成詞 → 合成武將 → 觸發技能/羈絆       │
        │      ↓ 戰力提升                          │
        │  下一波（更強）───────────────────────────┘
```

失敗條件：敵人抵達「大營」扣 1 生命，生命歸零則本局結束（初始 3 生命）。

## 3. 戰場（Board）

### 3.1 格位型別

| 型別 | 說明 |
|---|---|
| `PLOT` 空地 | 可放置字牌。有「淺色地」「深色地」兩種美術變體，機制相同 |
| `PATH` 道路 | 敵人行走。不可放置 |
| `BLOCK` 障礙 | 山石／樹林，不可放置、阻擋射線（可選規則，見 §11） |
| `SPAWN` 出兵口 | 敵人生成點，可多個 |
| `CAMP` 大營 | 敵人終點，玩家的血條 |

### 3.2 尺寸與地圖描述

- 邏輯棋盤：**9 欄 × 11～16 列**（各關不同）
- 固定關卡以字串陣列描述地圖：

```ts
map: [
  'S########',   // S=出兵口 C=大營 #=路 P=空地 .=障礙
  'PPPPPPPP#',
  '#########',
]
```

- 路徑用 BFS 從 SPAWN 求到 CAMP 的最短路，預先算成 waypoint 序列（不做即時尋路，敵人沿折線走，效能可預測）。

### 3.3 隨機地形（官渡、赤壁、五丈原）

三個後期關卡每一局的地圖都不同。**保證不會有死路**，而且是由構造保證，不是靠事後檢查：

1. 先畫出一條從最上列到最下列的連續走廊（隨機蛇形骨架）
2. 其餘格子才填成空地或障礙

隨機參數：出兵口與大營的欄位、每段橫走的長度與方向、每次下降 2 或 3 列、障礙密度。

走廊維持 **induced path** 性質——任兩個非相鄰的走廊格不會彼此貼邊。這帶來三個好處：

- 走廊兩側必然留有可放置的空地（不會生出無法佈陣的地圖）
- 沒有捷徑，所以 BFS 最短路一定等於生成時畫出的那條走廊，敵人不會走出設計者沒預期的路線
- 不會出現分岔造成的「假路口」

同一顆種子必然產生同一張地圖，回報 bug 時可完整重現。

## 4. 字牌（Glyph）— 最小單位

### 4.1 資料結構

```ts
interface GlyphDef {
  char: string          // '刀'
  category: GlyphCategory
  rarity: 1 | 2 | 3 | 4 // 抽取權重分級
  atk: number           // 基礎攻擊
  aps: number           // 每秒攻擊次數
  range: number         // 射程（格）
  shape: AttackShape    // 單體 / 穿透 / 濺射 / 範圍
  tags: string[]        // ['近戰','兵器'] 用於羈絆與相剋
  desc: string          // 「刀：近身直劈，傷害高。」
}
```

### 4.2 字的分類（設計骨幹）

| 類別 | 範例字 | 定位 |
|---|---|---|
| 兵器 | 刀 劍 矛 戟 弓 弩 斧 鞭 | 主要輸出。射程與型態差異大 |
| 兵種 | 騎 步 弓 盾 車 水 | 提供攻擊型態與抗性 |
| 姓氏 | 劉 關 張 趙 馬 黃 呂 曹 孫 諸 | 單獨放置很弱，是組將的鑰匙 |
| 名字 | 備 羽 飛 雲 超 蓋 興 苞 布 亮 | 同上 |
| 謀略 | 計 火 風 雷 毒 陣 令 | 控場與光環 |
| 經濟 | 糧 田 屯 商 | 不攻擊，每波結算產糧 |

> **關鍵設計**：姓氏字與名字字單獨戰力刻意壓低（約兵器字的 40%），製造「我抽到『關』，該不該先放著等『羽』」的兩難。

### 4.3 品質階級（疊合）

- 相同字、**相同品質**的兩張字牌相疊 → **升一階**，屬性 ×1.55
  - 兩個一階「火」→ 一個二階「火」；兩個二階「火」→ 一個三階「火」
- 上限五階。品質有名稱與顏色，一眼可辨：

| 階級 | 一階 | 二階 | 三階 | 四階 | 五階 |
|---|---|---|---|---|---|
| 顏色 | 灰 | 綠 | 藍 | 紫 | 金 |
| 屬性倍率 | ×1 | ×1.55 | ×2.40 | ×3.72 | ×5.77 |

- 疊合可在**棋盤上**（拖字牌到同字同階的字牌上）或**手牌之間**（拖卡片到卡片上）進行
- 手牌中出現可互相疊合的兩張卡時，卡片會亮藍框提示
- 光環字（陣、令）的光環強度也隨品質成長
- **品質會被武將繼承**：三階的「張」＋三階的「飛」組出的張飛，攻擊力是一階組合的 2.4 倍

## 5. 組字成將（本作核心）

### 5.1 判定規則

1. **相鄰連續**：同一列（橫）或同一欄（縱）上，連續的字牌
2. **順序正讀**：橫向左→右、縱向上→下，字串需完全命中配方表
3. **橫向與縱向各取一個最佳結果**（同方向多個配方命中時取稀有度最高者）
4. **字牌組成武將後不會消失**；武將是疊在字牌上的一層框
5. 已存在的武將不會重複產生（比對同名 + 同格子）

### 5.1b 武將是「疊上去的一層」，不是取代（M4b 改動）

這是本作最重要的資料模型決定，帶來三個玩法：

| 玩法 | 說明 |
|---|---|
| **持續強化** | 組成張飛之後，還能繼續把「張」或「飛」疊到對應格子上升階，張飛會立刻同步變強。不必在合成前就把字養好 |
| **個別改組** | 拖曳搬動的一律是單字。把「張遼」的「遼」拖走，張遼解除但「張」留在原地；補上「飛」就變成「張飛」 |
| **十字成雙** | 「張」的右邊放「遼」、下方放「飛」→ **同時組成張遼與張飛**，兩者共用「張」 |

規則細節：

- **武將等級 = 組成字牌的階級之和**（二階張 + 一階飛 = 3 級張飛）
- 武將攻擊 = Σ(成員字牌攻擊，已含階級倍率) × 階級倍率 → 「先組將再疊字」與「先疊字再組將」結果完全一致
- 已成為武將成員的字牌**不再單獨攻擊**（由武將那一層代表出手），也不再單獨投射光環或產糧，避免重複計算
- 共用字的武將各自獨立計算傷害，所以十字成雙相當於用 3 個字換到 2 名武將的火力——這是刻意給的獎勵
- 鏟除或搬走任一成員字牌，相關武將全部解除

### 5.2 配方表分層

| 階級 | 顏色 | 配方型態 | 範例 |
|---|---|---|---|
| 普通 | 白 | 兵種詞 | 弓兵、刀兵、騎兵、盾兵、槍兵 |
| 精良 | 藍 | 二字副將／謀略 | 黃蓋、馬岱、雷陣、火計、毒計 |
| 史詩 | 紫 | 二字名將 | 馬超、關興 |
| 傳說 | 金 | 二字頂級武將 | 張飛、趙雲、關羽、呂布、劉備、曹操 |
| 神話 | 紅 | 三字以上／特殊 | 諸葛亮 |

```ts
interface GeneralDef {
  name: '張飛'
  recipe: ['張', '飛']
  tier: 'legendary'
  size: 2                 // 占用格數
  stats: { atkMul: 2.4, apsMul: 1.1, range: 1, ... }  // 對輸入字牌總和取倍率
  skill: SkillDef         // 主動技（有 CD）
  passive: PassiveDef[]   // 被動
  bonds: string[]         // 參與哪些羈絆
}
```

### 5.3 武將戰力公式

```
武將 ATK = Σ(組成字牌 ATK × 等級係數) × tier 倍率 × (1 + 羈絆加成)
```

亦即**組成字牌的等級會繼承**——用 3 級的「張」和 3 級的「飛」組出的張飛，遠強於 1 級組出的張飛。這讓「先養字再組將」成為一條策略路線。

### 5.4 主動技（已實作）

技能自動施放：冷卻歸零且有合法目標時觸發；沒有目標則不消耗冷卻。
實作在 `sim/skills.ts`，共 6 種原型（範圍爆發／純控場／直線打擊／衝鋒／狙擊／全場），各武將只是套不同參數。

| 趙雲 | 〈七進七出〉16s | 無視射程，沿路徑衝鋒穿透最前 10 名 |
| 關羽 | 〈青龍偃月〉15s | 對前方 3 段路徑造成 320% 傷害 |

| 劉備 | 〈仁德〉45s | 恢復 1 點生命（滿血時不施放） |
| 呂布 | 〈無雙〉15s | 三段濺射爆發 |

### 5.5 羈絆（Bond）

場上同時存在指定武將／字時全域生效，是後期構築的核心：

| 羈絆 | 條件 | 效果 | 組合技 |
|---|---|---|---|
| 桃園結義 | 劉備 + 關羽 + 張飛 | 全體 ATK +30% | 〈三英戰呂布〉40s：合擊最強敵人並定身 |
| 五虎上將 | 關張趙馬黃（忠） | ATK +50%、攻速 +20% | 〈五虎齊出〉45s：清掃全路徑 |

| 江東基業 | 孫權 + 周瑜 + 黃蓋 | 攻速 +25% | 〈火燒赤壁〉40s：全場重度灼燒 |
| 臥龍鳳雛 | 諸葛亮 + 龐統 | 所有主動技冷卻 −30% | — |
| 魏武雄兵 | 曹操 + 張遼 | 全體 ATK +25% | — |
| 虎狼之師 | 4 支以上「部隊」 | 全體 ATK +15% | — |

## 6. 經濟系統

| 資源 | 取得 | 用途 |
|---|---|---|
| **糧** | 擊殺敵人 +1～3、每波結算固定收入、經濟字產出 | 征兵、重抽 |
| **生命** | 初始 3 | 敵人抵達大營扣 1 |

### 6.0 經濟字

不攻擊，改為每波結算時產糧。**產出 = income × 品質階級（線性，不吃 1.55 的指數倍率）**，
否則五階「商」會直接破壞經濟曲線。

| 字 | 每波產糧 | 說明 |
|---|---|---|
| 田 | 2 | 與「屯」相鄰可組成屯田 |
| 糧 | 3 | |
| 屯 | 4 | |
| 商 | 6 | 最強的單字經濟 |
| **屯田**（屯＋田） | **14** | 零件相加只有 6，合成後翻倍以上 |

這條路線的張力：經濟字占用的是能放攻擊單位的格子，前期投資會讓當下的防線變薄。

### 6.1 征兵（Recruit）

- 點擊「征兵」→ 花費糧，抽滿手牌（5 格）
- 花費公式：`cost = 8 + floor(wave × 1.6) + 2 × 本波已征兵次數`（本波結束後重置後項）

**抽卡收斂機制**（解決「字太多、想要的抽不到」）：

1. **每局字池**：一局只啟用字表的一部分（約 25～35 個字，依關卡）。兵器與兵種字永遠在池內；
   姓名字**成組加入**（選中「張飛」就把「張」「飛」一起放進池子），所以池裡不會有湊不成配方的孤兒字。
   開局會提示「本局可湊：張飛、關羽…」，讓玩家一開始就有方向。
2. **熟悉度加權**：已經在手上或場上的字，抽到的權重 ×3。抽卡會自動朝玩家正在經營的方向收斂。
3. **心願單**（玩家主動）：指定想要的字，權重再 ×5。與熟悉度加權相乘。

前兩者不需要玩家操作，第三個給玩家明確的主導權。

### 6.1b 心願單

點手牌上方的心願列 → 開啟挑選面板，列出**本局字池**的所有字，
每個字下面寫出它能組出哪些武將（例如「諸」下面寫「諸葛亮」），讓玩家看得出許願的價值。

- 心願中的字會在手牌上標一顆金色 ★
- 起始 1 格，局外養成「求賢令」可擴充到 3 格
- 只能許願池內的字——許池外的字不會有任何效果，所以直接擋掉並說明原因
- 心願是**本局有效**，換關會清空（它是戰術決定，不是永久設定）

實測效果：30 字池、單一心願，該字出現率由均勻的 3.3% 提升到 12%（約 3.6 倍）。

- 稀有度權重隨波次推移（讓後期抽到姓氏／名字字的機率上升）：

| 波次 | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| 1–5 | 70% | 25% | 5% | 0% |
| 6–12 | 50% | 32% | 15% | 3% |
| 13–20 | 35% | 33% | 24% | 8% |
| 21+ | 25% | 30% | 30% | 15% |

### 6.2 工具

- **熔爐**：分解模式。點一下切換，再點手牌即分解退糧；每局前 3 次有額外優惠
- **重抽**：花 `4 + 波次/2` 糧，把手牌上所有字換成新的（品質重置為一階，張數不變）
- **鏟子**：移除場上單位。字牌全額回收、武將只退 30% 糧
- **提示氣泡**：當手牌 + 場上可組成新配方時，畫面上方顯示「可組成：XXX」（最多 3 個，依稀有度排序）

## 7. 戰鬥數值

### 7.1 傷害公式

```
mitigation = DEF / (DEF + 60)
damage     = max(1, ATK × (1 − mitigation) × counterMul × critMul)
```

### 7.2 三向相剋（已實作，25%）

```
騎 → 弓 → 步 → 騎     (克制方 +25%，被克方 −25%)
```

我方兵種由字／武將的 tag 推導（`騎`／`弓`／`步`，其餘為無兵種不受影響）；
敵方兵種：賊與盾賊 = 步、快賊與賊將 = 騎、飛賊 = 弓。

### 7.2b 控場狀態

| 狀態 | 效果 | 來源 |
|---|---|---|
| 灼燒 | 每秒受到施加者攻擊力 × 倍率的傷害 | 火、毒、周瑜、火燒赤壁 |
| 減速 | 移速 −50% | 計、龐統、諸葛亮 |
| 定身 | 完全停止前進 | 斧、雷陣、張飛、張遼 |
| 易傷 | 受到的傷害 +30% | 張飛、龐統、三英戰呂布 |
| 擊退 | 沿路徑後退指定格數 | 風、馬超、鐵騎踏陣 |
| 連鎖 | 命中後追打附近敵人（60% 傷害） | 雷 |

**賊將（BOSS）免疫定身與擊退**，但吃灼燒、減速與易傷——這讓控場流不會完全癱瘓 BOSS，
也讓玩家在 BOSS 波必須有實質輸出。

### 7.3 目標選擇

預設「最前方（離大營最近）」，可在單位面板切換：最前／最近／最高血量／最密集。

### 7.4 敵人

| 敵人 | 特性 |
|---|---|
| 賊 | 基礎雜兵 |
| 盾賊 | DEF 高，怕穿透與謀略 |
| 快賊 | 移速 ×2，血薄 |
| 飛賊 | 直線飛越障礙，只有射程 ≥2 的單位可攻擊 |
| 妖道 | 為周圍敵人回血 |

- **兵書**（已實作）：花「聲望」買永久升級。

- **藏書閣**（不做了）：原本要用聲望解鎖新字加入抽卡池，但 §6.1 的「每局字池」已經
  從另一個方向解決了字太發散的問題；再加一層解鎖只會讓前期選擇更貧乏。

```
┌────────────────────────────┐
│ ⏸  糧15   〔巨鹿〕   第9波 │  頂部狀態列
├────────────────────────────┤
│                            │
│        棋盤（Canvas）       │  可上下捲動（若地圖高於視窗）

```

- 點擊棋盤 → 底部彈出資訊卡。**面板以「格子」為單位**：先講這一格的字（品質、屬性），
  再列出它參與的武將（可能兩個，例如十字成雙）
- 速度控制：1× / 2× / 3×；左上 ☰ 回選單
- **UI 尺寸全部由 `--ui` 這個 CSS 變數驅動**，數值來自 `#app` 的實際大小
  （`min(寬/27, 高/56)`，夾在 9.5px～18px）。棋盤格與文字因此永遠等比縮放，
  不會出現「棋盤變大但文字沒變」的失衡
- 全部文字用系統 CJK 字體渲染，**不使用任何外部圖片資源**（美術靠 Canvas 繪製的紙紋、墨線、印章色塊）

### 9.1 「這是誰打的？」— 攻擊特效的辨識設計

塔防最容易糊掉的就是一堆單位同時開火時分不出誰是誰。本作用四個同時生效的線索解決：

1. **形狀**：刀劍是弧形斬擊、弓弩是細箭、矛槍是帶菱形槍尖的直刺、火是火球加拖尾、
   雷是鋸齒閃電、毒是虛線加氣泡、風是新月氣旋、騎步是塵土弧、「計」則是**把字本身丟出去**
2. **顏色**：每種特效一個固定色（墨黑／墨綠／靛藍／橘紅／紫／草綠／天藍／土褐）
3. **標籤**：命中點會浮現攻擊者的字（武將顯示名字），跟著特效一起淡出
4. **來源閃光**：開火的單位本身會閃一下同色外框

階級越高的武將線條越粗（傳說 ×1.5），所以強力單位的攻擊在畫面上也更醒目。

### 9.2 音效與粒子（M5）

兩者都由 **sim 的事件佇列** 驅動：`sim` 只往 `state.events` 推純資料
（`kill` / `combine` / `skill` / `combo` / `leak` / `waveClear`…），
app 層每幀 drain 一次轉成音效與粒子。這讓 `sim` 依然不知道 Web Audio 或 canvas 的存在。

**音效**：全部用 Web Audio **即時合成**，專案不放任何音檔。
每個音效是一組「振盪器 + 滑音 + 白噪音」的配方（`core/audio.ts` 的 `RECIPES`）。

- 攻擊音依特效種類分流（刀劍／弓箭／火／雷／其他），所以聽覺也能分辨是誰在打
- 攻擊類音效**必須節流**（每種 0.08～0.12 秒一次），否則後期每秒 20 次攻擊會變成噪音牆
- 傳說以上的成將多一層低音鑼，聽得出「這次不一樣」
- 右上角 ♪ 可靜音，設定存在 localStorage

**粒子**：`render/particles.ts`，上限 240 顆，只有位置／速度／壽命／顏色／重力。
擊殺噴墨點、成將噴階級色環（階級越高越多）、技能噴金色火花、組合技全屏噴發、漏怪在大營潑紅。

## 10. 技術規格

### 10.1 選擇：TypeScript + Vite + Canvas 2D（無遊戲引擎）

理由（我需要能「完整自己做完」）：

| 考量 | 說明 |
|---|---|
| 零美術資產 | 本作視覺主體是**漢字**，用 Canvas 的 `fillText` 就是最終畫面品質，不需要美術外包，這是本專案最大的技術優勢 |
| 我可直接驗證 | 我能啟動 dev server、用瀏覽器工具截圖與讀 console，實際看到並修正畫面 |
| 你可零安裝試玩 | `npm run dev` 或直接開瀏覽器；也能 build 成靜態檔丟任何空間 |
| 邏輯可測 | 組詞判定、傷害公式、抽卡權重都是純函式，用 Vitest 寫單元測試，改數值不怕壞 |
| 對比 Unity/Godot | 需要 GUI 編輯器操作場景與 prefab，我無法可靠地代你完成，且對「純文字」畫面是過度工程 |
| 對比 pygame | 中文字體需自備字型檔、分享困難、觸控與 UI 都得自己重造 |

### 10.2 架構

```
src/
├─ main.ts                 進入點、canvas 初始化、resize
├─ core/
│  ├─ loop.ts              固定步長 60Hz 模擬 + 可變 render
│  ├─ rng.ts               mulberry32 種子隨機（可重現、可測試）
│  ├─ events.ts            輕量事件總線
│  └─ save.ts              localStorage 存檔（版本遷移）
├─ sim/                    ★ 純邏輯，不碰 DOM，全部可單元測試
│  ├─ state.ts             GameState 型別（單一狀態樹）
│  ├─ board.ts             格位、放置合法性、路徑 BFS
│  ├─ combine.ts           ★ 組詞判定引擎
│  ├─ combat.ts            索敵、傷害、投射物
│  ├─ waves.ts             波次生成器
│  ├─ economy.ts           征兵成本、抽卡權重
│  └─ bonds.ts             羈絆計算
├─ data/                   ★ 純資料，你要改平衡就改這裡
│  ├─ glyphs.ts            所有字定義
│  ├─ generals.ts          所有配方與技能
│  ├─ enemies.ts
│  ├─ bonds.ts
│  └─ levels/*.ts
├─ render/
│  ├─ renderer.ts          主繪製迴圈
│  ├─ theme.ts             水墨紙感配色、字級
│  ├─ tiles.ts / units.ts / effects.ts
│  └─ camera.ts            縮放與置中
├─ ui/                     DOM/CSS 疊層（HUD、手牌、面板、彈窗）
└─ input/pointer.ts        指標事件、拖放、長按
```

**設計原則**

- `sim/` 與 `data/` 完全不依賴 render/DOM → 可在 Node 環境跑戰鬥模擬，做**自動平衡測試**（例如「AI 隨機打法在第幾波陣亡」跑 1000 局統計）
- 單一 `GameState` 狀態樹 + 純函式 reducer，方便存檔、回放、除錯
- 固定步長模擬（16.67ms）確保不同裝置行為一致；渲染插值
- 種子隨機：同一種子 → 同一場對局，bug 可 100% 重現

### 10.3 相依套件（刻意極少）

`vite`、`typescript`、`vitest`、`tsx`、`@types/node`。**執行期零相依。**

連 PWA 也沒有引入 `vite-plugin-pwa` / `workbox` —— 整個離線需求只是「把打包出來的檔案
預先快取起來」，用 30 行自己寫（`vite.config.ts` 的 `pwaPlugin()`）比拉進一整套框架更好維護。

### 10.4 PWA（可安裝、離線可玩）

打包結果就是一個 PWA，手機與電腦都能安裝：

| 元件 | 位置 | 說明 |
|---|---|---|
| Manifest | `public/manifest.webmanifest` | 名稱、直式鎖定、主題色、圖示 |
| 圖示 | `public/icons/icon.svg` | 可縮放；設計成 maskable-safe（內容都在中心 80% 安全區內） |
| iOS 圖示 | `public/icons/icon-192.png` | iOS 的 apple-touch-icon 不吃 SVG，必須給 PNG |
| Service Worker | build 時產生 `dist/sw.js` | precache 清單自動帶上 Vite 加了 hash 的檔名 |
| 註冊 | `src/core/pwa.ts` | 只在 production 註冊；開發模式不裝 SW |

快取策略：

- **導覽請求**走 network-first（才拿得到新版），離線時回退到快取的首頁
- **其他資源**走 cache-first —— 檔名帶 hash，內容不會變，快取永遠有效
- 版本號由「檔名清單 + SW 原始碼」一起 hash；換版時 activate 會清掉舊快取

因為遊戲本身零外部資源、進度存在 localStorage，所以離線體驗與線上完全一致。
